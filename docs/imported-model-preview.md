# 外部模型默认预览逻辑核查

核查日期：2026-10-21。基线提交：`043cefb`。本项仅核实行为，没有修改导入、模型文件或查看器实现。

## 结论

**没有来源提示的外部模型，目前使用与单图模型相同的默认显示朝向与取景分支。** 系统将其来源保留为“未知”，随后使用默认回退；不会识别它来自哪种重建工具，也不会根据外观猜测它是单图还是视频模型。

这个行为同时覆盖模型资产库的普通文件导入，以及单个文件的临时预览。已有明确预览信息或在本浏览器为该资产保存过预览设置时，实际结果可以不同。

## 打开模型时发生什么

| 环节 | 普通外部导入的结果 | 用户看到的影响 |
| --- | --- | --- |
| 来源与元数据 | `source_media_type=null`、`viewer_orientation=unknown`，没有默认相机或显示变换 | 无法直接恢复原项目保存在 sidecar 中的初始镜头 |
| 默认显示变换 | 无覆盖设置时，使用绕 X 轴旋转180°、等比放大2倍的既有显示基准 | 与采用其它展示基准的编辑器相比，方向或显示大小可能不同 |
| 初始相机 | 从既有 `(0,0,1)` 相机位置出发，依据模型前侧估计观察中心 | 部分模型可能贴近相机、只看到局部，不能保证首次就完整取景 |
| 包围盒回退 | 默认分支只在横向/纵向中心偏移超过阈值时，改为以包围盒中心取景 | 即使模型较大，居中时也不一定触发拉远；远处残留点可能影响取景 |
| 操作限制 | 继续使用当前的“正面视角”开关状态 | 开启时仍有限制，不会因模型是外部导入而自动切换自由环绕 |

生成的视频模型还有独立来源修正，且有效的保存相机优先于包围盒取景。普通外部导入没有这些信息，因此两者并不保证从同一角度打开。

默认分支的包围盒偏移判据为：XY中心偏移大于 `max(0.2, 最长轴尺寸 × 0.25)`。触发后才使用包围盒中心并按当前画幅计算取景距离；不能把它描述为“所有外部模型都自动完整居中”。

## 文件坐标与观察效果

- 导入是保存文件副本，默认旋转和缩放属于预览层，不会在导入时写进模型坐标或原点。
- 如果从本项目下载模型文件后单独重新导入，它会成为新的导入资产。原生成资产的 `.meta.json` 来源、`viewer_camera` 与 `viewer_transform` 不会自动随该文件带入。
- 因而“模型文件相同、打开时方向或镜头不同”是当前预览回退可能造成的结果，不能仅凭画面推断文件已被改坏。
- 本结论不代表所有外部模型都会显示异常。实际效果取决于文件自身的坐标、尺寸、点分布、格式解码，以及当前资产的预览覆盖设置。

## 核查依据与验证

- [导入记录与元数据投影](../backend/services/model_assets.py)：普通导入记录将朝向设为 unknown，不自动接收生成资产的 sidecar。
- [临时文件预览](../frontend/src/App.tsx)：同样传递未知来源和朝向。
- [朝向解析](../frontend/src/utils/viewerOrientation.ts)：未知来源回退 default；明确视频来源使用独立分支。
- [默认显示变换](../frontend/src/constants/viewerCoordinates.ts)、[资产预览覆盖](../frontend/src/store/useAppStore.ts)：默认基准与已保存的浏览器覆盖设置共同决定显示变换。
- [初始相机与包围盒回退](../frontend/src/hooks/useViewer.ts)：保存相机优先，其余走默认或按条件触发的包围盒取景。
- 既有前端方向/取景测试24项与后端来源/朝向测试7项通过。
- 隔离临时工作区实际导入已有验证用SPZ文件，确认来源未知、相机与变换为空；导入后可下载文件与原文件SHA256一致，源文件SHA256不变。没有在用户原工作区新增资产。

本轮没有更改实现、重写模型、重建封面，未做多个外部编辑器的完整视觉对照。通用外部模型展示基准、首次完整取景及可选来源提示属于后续独立改进范围。
