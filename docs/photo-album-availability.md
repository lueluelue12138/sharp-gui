# 相册目录失效处理

- 相册目录不可用时保留记录和索引，侧栏显示本地化原因，禁用打开；重新扫描和移除记录仍可使用。
- 页面已有媒体时，定期检查以及窗口重新聚焦会更新可用性。相册失效后清空网格、选择与预览，显示恢复说明，不再渲染旧媒体的空缩略图。
- 原目录重新连接后恢复浏览。源目录仍在但已变空时提示“相册源文件已移走或删除”；显式重新扫描可确认它现在是真正的空相册。
- 路径身份计算的容错仅用于配置 ID，不用于放宽文件访问的真实路径校验。API 不返回绝对相册路径或操作系统异常细节。

## 跨平台边界

Windows 拔盘、macOS `/Volumes` 和 Linux `/media` / `/mnt` 目录失效走同一检查逻辑。新扫描记录所在文件系统，识别挂载点仍存在、但原文件系统已卸载的情况；旧索引未记录设备信息时，重新扫描后获得这项保护。

验证在 Windows 运行：覆盖缺失相册启动、Windows/macOS/Linux 路径形式、根目录变成文件、权限和 I/O 异常、挂载设备变化、扫描途中断开、重连恢复及全部媒体移出空目录。macOS 和 Linux 的卸载及错误情形使用模拟测试，未宣称完成两平台实机拔盘测试。

目录仍有其它文件或子目录、但某些媒体已被单独迁移时，需要重新扫描同步索引；普通列表不会为此遍历整个相册。
