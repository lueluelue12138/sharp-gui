# 全局配置与换包恢复

## 换包后会保留什么

同一系统用户运行新版 Sharp GUI 时，默认共用一份安装目录之外的配置。它记住工作区、按工作区分组的相册、默认模型格式、视频重建默认参数和局域网门禁设置。

模型、来源媒体、资产资料与图库索引仍从原工作区读取，保留原模型和相册的 ID。配置不会复制、移动或删除这些数据。**如果工作区位于旧便携包内，请保留整个旧工作区，不能因为换包成功就删除旧目录。** 可以在设置中查看工作区位置。

浏览器中的查看器偏好等 localStorage 设置仍由当前浏览器保存，不会写入服务端全局配置。证书、Python/CUDA、Brush、COLMAP 和安装级更新状态也不属于这份配置，不会在不同完整包之间迁移。

## 默认位置

| 系统 | 配置文件 | 全新用户的默认工作区 |
| --- | --- | --- |
| Windows | `%LOCALAPPDATA%\SharpGUI\config.json` | `%LOCALAPPDATA%\SharpGUI\workspace` |
| macOS | `~/Library/Application Support/SharpGUI/config.json` | `~/Library/Application Support/SharpGUI/workspace` |
| Linux | `${XDG_CONFIG_HOME:-~/.config}/sharp-gui/config.json` | `${XDG_DATA_HOME:-~/.local/share}/sharp-gui/workspace` |

Windows 缺少 `LOCALAPPDATA` 时使用当前用户的 `~/AppData/Local`。设置中的「配置存储」显示实际文件位置，仅本机 owner 可见。

加载顺序：

1. 设置了非空 `SHARP_CONFIG_FILE` 时，**只使用指定文件**，不读取或合并默认全局配置，也不自动导入包内配置。建议使用绝对路径。该隔离方式适合开发、测试及不同实例；原有显式配置的默认工作区语义保持不变。
2. 否则使用 `SHARP_CONFIG_HOME/config.json`，或上表的系统默认位置。`SHARP_CONFIG_HOME` 必须是绝对目录；设置它时，全新用户工作区默认在这个目录的 `workspace/` 下。
3. 全局文件仅在首次建立时自动导入当前安装目录的 `config.json`。旧文件保持原样，未知字段与访问码哈希、会话密钥一并保留；相对路径按旧文件所在目录解析。之后包内的旧文件不会覆盖全局文件。
4. 首次建立时没有旧配置，但当前包已存在非空的已知用户数据目录，会沿用本包作为旧工作区；否则创建稳定的全新工作区。此探测只检查本包已知目录的首个条目，不扫描其他硬盘或安装。

首次导入只在正常启动读取配置时发生；仅导入 Python 模块或查询配置路径不会写入文件。已经建立过的全局配置被删掉后不会默默重新初始化。

## 从没有全局配置的旧版本换包

如果新包第一次运行时，旧包的配置还没有登记到全局位置，应用无法知道旧包放在哪个硬盘。可以：

1. 在新版打开「设置 → 配置存储 → 从旧版本恢复配置」。
2. 选择**包含旧 `config.json` 的文件夹**。系统目录选择器不可用时，可输入绝对路径。
3. 核对预览中的工作区和相册配置数量。数量包含所有工作区分桶，不代表每个相册当前都在线。
4. 确认「恢复并重启」。当前配置先备份为同目录的 `config.json.before-restore-<随机标识>.bak`，然后保存旧配置，并通过现有服务重启流程生效。
5. 页面会在确认新服务启动后刷新。如果提示配置已保存但重启未确认，请手动重启应用。恢复的门禁设置可能要求重新登录，也可能改变局域网访问状态。

恢复是替换整份配置，不合并两套相册或模型资料。预览和取消不会修改配置；确认前源文件或当前配置发生变化会拒绝操作，需要重新预览。正在提交或运行生成任务、目标工作区被其他实例占用、目录不可写时也会拒绝。确认后到重启完成前拒绝新的写请求，防止新旧工作区混用。原目录和原媒体始终保留。

工作区锁预检通过并不保证重启时仍空闲：如果另一个实例抢先占用，启动仍会安全失败，需要关闭冲突实例后重启。

## 备份与故障处理

- 普通保存使用进程锁、内容修订检查和同目录临时文件原子替换。并发修改返回冲突，不会用过期内容覆盖新配置。锁文件残留不等于进程仍持锁，请勿在运行时删除它。
- 配置 JSON 损坏、结构无效、已初始化后文件丢失或权限不足时，应用明确失败；不会静默换成空工作区或关闭门禁。修复路径/权限或恢复备份后再启动。
- 手工恢复前关闭所有共用该配置的 Sharp GUI 实例，先另存当前配置，再将选定有效备份复制为活动配置文件。保留现有 `.lock` 文件即可；不要通过删除锁标记来绕过丢失保护。
- 备份只含配置，**不含模型、原图、视频或工作区索引**。完整数据备份需另外保留工作区及外部相册目录。
- 配置及备份含访问码哈希和会话密钥，不要上传、分享或放进公共目录。文件接口禁止下载活动配置、恢复备份和临时文件；新建目录/文件使用用户私有权限，Windows 沿用用户目录的 ACL。
- 全局配置属于当前系统账号。更换账号、搬到另一台电脑或另一操作系统不会自动同步；原磁盘路径也不能跨系统直接通用。
- 同一账号多套包默认共享配置；需互相独立时，各自指定 `SHARP_CONFIG_FILE` 和不同工作区。一个工作区同时只允许一个服务实例。
- 本功能之前的旧应用仍只认识包内配置。新版不会反向同步旧文件；降级使用旧应用前请确认它的配置和工作区，避免误以为全局设置已经同步。

## 验证范围

自动化覆盖 Windows/macOS/Linux 的路径选择分支、显式配置隔离、两套安装读取同一工作区后的模型/相册身份、并发初始化、过期保存、写入失败、配置损坏/丢失、恢复备份、任务/锁冲突、门禁和敏感文件保护。设置界面恢复流程使用隔离工作区验证，不操作真实用户媒体。

平台路径分支测试不等于在 macOS/Linux 构建并运行了完整便携包；本项不变更依赖、安装器或便携运行时版本。
