## Context

已有管线在 Brush 非零退出后调用 `contains_oom`，最多重试一次。其宽泛子串包含 `memoryerror` 和 `failed to allocate memory`，会把主机内存与不明确的分配错误也解释为显存不足。0.6.0 的固定运行时和 CLI 与本项目已验证版本不同；本轮只借鉴故障分型思路，独立实现。

## Goals / Non-Goals

**Goals:** 明确显存不足才重试；设备中断和主机内存不足返回不同错误；普通失败保留尾部诊断；正常成功路径与质量设置不变。

**Non-Goals:** 更换 Brush/COLMAP、调整增密/分辨率/帧数、引入透明素材或更改二视图轨迹策略、实现 MCP/任务 UI/补拍。

## Decisions

1. 采用统一分类函数，同时供错误提示与重试资格判断使用。Why：避免两处识别范围不同。备选：各处独立正则；容易出现提示为设备失联但仍降低预算的矛盾。
2. 明确设备丢失标记优先终止；CUDA/HIP/Vulkan 明确显存错误保留重试；识别主机内存错误；保留 WGPU/PyTorch 的 `OutOfMemory` / `OutOfMemoryError` 枚举。Why：减少无依据降预算。备选：直接使用上游所有宽泛关键词；会把 BufferTooBig、普通 allocation failed 和系统 RAM 不足混为一谈。
3. 复用任务队列按错误码查找 `videoReconError` 的既有逻辑，新增中英文设备中断与主机内存提示。Why：无需新组件或接口字段。备选：新建诊断面板；范围过大。

## Risks / Trade-offs

- [驱动输出不统一] -> 未识别或含糊错误按普通失败返回原日志，不擅自改变训练预算。
- [同一输出含设备丢失与分配错误] -> 保守按设备中断停止；不承诺降低高斯数能解决驱动重置。
- [单元测试不能证明画质提高] -> 成功路径参数不改，保留原质量对照；文档明确本轮只验证故障行为。
- [运行时升级的 CLI/增密语义发生变化] -> 记录固定版本差异，另行做完整引擎升级与画质回归。

## Migration Plan

不迁移数据或运行时；应用代码与双语文案、构建产物同批提交。回退本次代码提交即可恢复旧分类，模型、项目和配置文件不受影响。
