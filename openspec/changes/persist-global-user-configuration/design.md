## Context

runtime.get_config_file 当前返回包内 config.json。图库配置按 workspace 分桶，模型和索引均位于工作区；配置只需保留原路径，无需复制大文件。所有配置写入经 backend.config.save_config，适合统一接入持久化。

## Goals / Non-Goals

**Goals:** 换包共享配置、原工作区及相册；自动迁移本安装旧配置；支持明确选择旧包恢复；原子保存和冲突保护；保留显式配置隔离。

**Non-Goals:** 自动移动/删除模型、全盘寻找旧包、合并多套配置、改变视频依赖、同步浏览器 localStorage、共享不同操作系统的路径。

## Decisions

1. 默认 Windows 使用 LOCALAPPDATA/SharpGUI，macOS 使用 ~/Library/Application Support/SharpGUI，Linux 使用 XDG_CONFIG_HOME/sharp-gui。Why：独立于解压目录；备选包内配置不能满足换包需求。SHARP_CONFIG_HOME 可指定隔离用户配置目录，SHARP_CONFIG_FILE 优先且完全绕过全局迁移。
2. 全局文件存在时优先使用；仅首次缺失时从当前安装 config.json 导入，原文件不改。新用户工作区使用稳定用户数据位置；遗留配置缺少 workspace 时沿用旧包根目录，已有相对路径按旧包目录解析。Why：保持模型身份和分桶；备选直接换成新包根目录会使数据失联。
3. 系统文件锁、进程内锁、同目录临时文件 fsync/replace；读取配置携带不可序列化的来源与内容修订属性，保存时拒绝过期写入。初始化标记防止已建立配置被删除后自动回落到空配置。Why：保护密钥与数据；备选直接覆盖存在损坏及竞态风险。
4. owner-only 恢复先预览旧包摘要，再确认；校验旧源与当前配置指纹，检查任务和目标工作区，先备份当前配置再提交，用户确认后通过既有重启流程生效。Why：未知旧包无法自动定位；备选按时间扫描/猜选可能载入错误账号或相册。
5. 设置仅向 owner 显示配置位置；错误码本地化、损坏时关闭访问而不默默重置。Why：配置含门禁密钥；备选默认值回退可能弱化门禁。

## Risks / Trade-offs

- [用户删除旧工作区] -> 说明配置是路径记忆，模型仍在原目录；本功能不搬动大型数据。
- [旧版本没有登记全局配置] -> 新包提供选择旧包恢复入口，不假称可找到任意盘符旧目录。
- [旧盘离线] -> 自动导入保留路径；手动恢复提交前预检工作区，不覆盖当前有效配置。
- [配置损坏或权限不足] -> 保留文件并报稳定错误，保留旧包与恢复前备份作为回退来源。
- [多个实例或设置请求并发] -> 锁与内容修订防止交叉写入；测试覆盖过期保存和两个初始化进程。
- [运行时更新] -> 不增加依赖或修改安装/打包脚本；深导入无配置落盘副作用。

## Migration Plan

在现有安装首次运行自动导入；之后不同包读取同一用户配置。自定义实例设置 SHARP_CONFIG_FILE。旧配置保持原样，恢复确认前保留目标备份，可手动还原；不自动恢复损坏配置或替换工作区。
