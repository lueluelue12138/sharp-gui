## Context

Settings 的所有草稿已在同一父组件中，配置恢复和更新独立封装。已有 Button、玻璃态输入/分段控件、提示与确认组件可复用。自定义设置弹层已提供固定标题和底栏，保留它的视觉表面，仅调整内部导航和滚动布局。

## Goals / Non-Goals

**Goals:** 查找更快、分组清晰、切组不丢草稿、owner-only 功能不泄露、按需请求不覆盖未保存值、键盘/触控可达。

**Non-Goals:** 不引入新依赖或全局导航系统，不改变设置字段/API、训练画质或已有即时预览行为，不重做通用 Modal。

## Decisions

1. 左导航加单内容区，窄屏变为可见的紧凑六格顶部导航；使用项目现有玻璃面板、Button、图标和 Token。替代再加一个长列表/仅折叠标题仍难扫描，横向窄屏导航可能隐藏最后入口。
2. 所有草稿仍在 Settings 父组件，面板用 hidden 控制可见性并提供 tablist/tab/tabpanel；导航支持方向键、Home/End，切组内容回顶。替代拆分独立表单会改变保存和取消语义。
3. 常规含工作区/配置恢复/格式/批转换，图库仅缓存，视频仅默认参数与依赖，查看器保留预设/特效/高级项，访问安全含门禁/远程会话，更新独立。owner-only 图库/更新导航对远程隐藏，常规保留远程本机格式偏好。
4. 缓存与视频状态首次进入时加载；诊断响应只更新诊断，不重置本地视频草稿。更新首次进入后在本次设置会话中继续保持激活，切组不停止已有更新轮询；不访问更新分组就不加载。
5. 底部统一保存所有分组草稿，导航显示轻量未保存标记；保留即时查看器预设提示，明确即时项不由取消回滚。

## Risks / Trade-offs

- [标签切换造成草稿丢失] → 状态保留在父层，不因 active group 重新初始化。
- [隐藏分组仍触发耗时请求] → 按首次访问 gating，并验证请求日志。
- [刷新诊断覆盖视频编辑] → 诊断与初始默认值加载分开，慢请求测试验证。
- [窄屏或英文标签拥挤] → 3 列布局、可换行、稳定按钮高度及内容 min-width:0，实机浏览器验证。
- [权限变化时停留已隐藏组] → 可见组推导安全回退，服务端权限规则保持原样。
- [即时设置/保存设置混淆] → 保留原行为并在查看器分组明确说明。
