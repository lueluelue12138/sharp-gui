## Context

图片任务复制输入文件但未记录相册 ID；视频已有 source_media_id。模型摘要持久化到工作区资产索引，编辑副本继承部分来源信息。图库分页和模型库分页互相独立。

## Goals / Non-Goals

**Goals:** 一份原片关联多个结果，可靠标识任务与完成状态；原片汇总相册；选择及默认模型；跨保存、删除、刷新保持一致。

**Non-Goals:** 多图训练、模型几何或坐标变更、额外复制视频、无原片导入模型的来源猜测。

## Decisions

1. 来源身份在任务/sidecar 中持久化，内容校验用于重复输入去重。Why：同名文件不是同一原片，编辑来源模型删除后关系仍须存活。备选：按名称关联不可靠；仅前端关联不能覆盖分页和重启。
2. 模型来源摘要随已有资产 catalog 增量更新；默认模型资料保存在同一索引的扩展字段，沿用原子写入和锁。Why：避免第二份模型资产真相源。备选：新数据库/独立全局媒体路径表增加迁移与一致性负担。
3. 系统相册使用稳定保留 ID 和受控媒体解析，复用图片/视频预览、缩略图与下载。Why：同一原片不额外复制视频。备选：实体相册会重复占用空间。
4. 多模型未设默认时展示选择面板，设置默认后支持直接打开与全部版本入口。Why：最新编辑副本不一定是最佳结果。备选：自动打开最近模型会改变用户预期。
5. 历史来源补齐在有界后台任务执行，常规分页只读摘要。Why：图库启动不能同步读遍视频和图片。备选：每次列表内容哈希导致大图库 IO 阻塞。
6. 前端关联刷新使用独立修订号与请求代次，任务完成、编辑保存和删除触发精确失效。Why：不可依赖受筛选的模型库当前页。备选：刷新整页丢失滚动和选择上下文。

## Risks / Trade-offs

- [历史来源缺失或歧义] -> 只接受明确引用/谱系或相同内容校验；保持未关联并展示修复状态。
- [原片同路径替换] -> 新任务记录来源版本，关联校验避免当前文件错误继承旧模型。
- [离线磁盘] -> 模型访问独立于原片；保存原图副本可用时仍预览，视频只保留失效提示与已有封面。
- [并发保存/删除/默认选择] -> 复用资产索引锁、原子提交并重新确认资产归属与可用性。
- [大媒体校验成本] -> 首次来源确认流式计算、缓存文件版本；迁移后台运行，不在暖分页重复计算。

## Migration Plan

新增可选 sidecar/索引字段，旧字段继续可读；历史恢复保留原元数据。旧代码仍能读取模型文件与忽略扩展资料；回退源码不删除新资料。验证重复生成、编辑链、源模型删除、覆盖、同名异内容、离线/替换文件、权限及不扫描的暖查询。
